How It Works

ShieldKnot AI is a defense-only demo. Components shown as active are implemented locally; demo incident scenarios are explicitly labelled simulated.

Implemented pipeline

Transaction CSV
local dataset
→
Fraud Model
joblib probability scorer
→
Spike Detector
risk-density windows
→
Abuse-Ring Sentinel
shared device / IP grouping
→
Response Policy
deterministic + human review

1 Fraud scoring

The API loads the model bundle from models/fraud_model.joblib and scores the transaction features in the request.
POST /api/score

2 Fraud-spike detector

Recent high-risk density is compared with a baseline over the local dataset. A density lift at or above 1.4 creates a detector incident.
GET /api/spike

3 Return-risk scorer

A deterministic scorer combines return rate, velocity, amount anomaly, merchant risk, and account age. It always requires human review.
POST /api/return-risk

4 Chargeback evidence responder

The backend builds a structured evidence package from the transaction and model output. It prepares a reviewer response but never submits a dispute automatically.
GET/POST /api/chargeback-evidence/…

5 Abuse-ring sentinel

High-risk transactions are grouped by shared device and IP identifiers. Groups with at least three members are surfaced as candidate rings.
GET /api/abuse-ring

6 Response policy + reward

The deterministic policy maps risk bands to review recommendations without auto-blocking. Recorded outcomes are scored by the local reward calculator.
GET /api/response-policy · POST /api/outcomes
